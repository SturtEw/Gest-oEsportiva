## Changes Made

### 1. Make the Vite debug preLaunchTask safe to rerun
- **File:** `.vscode/tasks.json`
- **Change:** Route the background task through a dedicated PowerShell startup script instead of invoking `npm` directly. The task retains a readiness matcher for `127.0.0.1:5173`.
- **Why:** The original command used `--strictPort`, which exits with code 1 whenever port 5173 is already occupied, including when the developer has already started the portal.
- **Revert:** Restore the original `npm run dev` command and arguments in the task.

### 2. Check, reuse, and start the correct Vite server
- **File:** `.vscode/start-vite-debug.ps1` (new)
- **Change:** Check the existing listener on port 5173. Reuse it only when the page references the student portal entry point and its `/@vite/client` endpoint responds as a Vite server. Otherwise show an actionable port-conflict error. If the port is free, validate the frontend manifest and local Vite installation, then launch Vite with the original strict port and loopback host. Keep the PowerShell script's user-facing messages ASCII-safe for older Windows PowerShell encoding defaults.
- **Why:** Avoid duplicate-server startup failures without silently debugging an unrelated process on the same port.
- **Revert:** Remove `.vscode/start-vite-debug.ps1` and restore the original task command.

### 3. Align the browser debugger with the loopback host
- **File:** `.vscode/launch.json`
- **Change:** Point the Edge and Chrome launch configurations to `http://127.0.0.1:5173`.
- **Why:** Keep the debug browser URL consistent with Vite's explicit loopback bind address.
- **Revert:** Restore both launch URLs to `http://localhost:5173`.
